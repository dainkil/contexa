# Contexa 최종 요구사항 명세서

| 항목 | 내용 |
|---|---|
| 문서 버전 | 1.0 |
| 작성일 | 2026-11-08 |
| 기준 | 최종 서비스 시나리오 CX-01~CX-11 |
| 적용 범위 | 한국어·영어·아랍어 기반 MVP |
| 입력 | 회의 전사문, 업무 문서, 규정집, 메모, 참석자·협력사 명단, 선택적 원본 녹음 |
| 출력 | 맥락 브리핑, 근거 기반 답변, 고유명사 확인 결과, 결정 이력, 업무 목록, 누적 위키, 보고서·메일·메시지 초안 |

본 문서의 요구사항은 MVP의 필수 구현·검증 기준이다. 성능·정확도의 수치는 실측 결과가 아닌 **제안 수용 목표**이며, 시험 조건과 함께 검증한다. 고유명사 확정은 근거와 사용자 검토를 통해 표기·지칭 대상을 확인하는 절차를 뜻한다.

녹음 자동 전사, 이름 구간 자동 재인식, 스캔 문서 OCR, 외부 서비스 자동 동기화, 메일·메시지 실제 발송은 본 명세의 구현 범위에서 제외한다.

## 1. 기능 요구사항

### 1.1 계정·프로젝트·접근권한

| ID | 요구사항 | 상세 명세 | 수용 기준 |
|---|---|---|---|
| FR-001 | 사용자 인증 | 로그인·로그아웃을 제공하고 인증된 사용자 식별자를 유지해야 한다. | 비인증 사용자가 프로젝트 자료를 조회·변경할 수 없다. |
| FR-002 | 프로젝트 관리 | 워크스페이스 안에서 프로젝트를 생성하고 제목·설명·구성원을 관리할 수 있어야 한다. | 자료·결정·업무·이름 사전이 소속 프로젝트와 연결된다. |
| FR-003 | 구성원 관리 | 관리자는 구성원을 초대·제외하고 조회자·편집자·검토자·관리자 역할을 지정할 수 있어야 한다. | 조회자는 내용을 변경할 수 없고, 확정·승인은 지정 검토자 또는 해당 권한을 가진 관리자만 수행한다. |
| FR-004 | 자료 공개 범위 | 자료별 개인용·프로젝트 공용 범위를 설정하고, 열람·편집·외부 공유 허용 여부를 구분해야 한다. | 개인 자료가 공용 검색·위키에 포함되지 않으며 외부 공유가 금지된 내용은 외부용 초안에 반영되지 않는다. |
| FR-005 | 권한 변경 반영 | 구성원 제외·자료 권한 변경을 원문과 기존 생성 결과에 반영해야 한다. | 변경 이후 조회·검색·다운로드·내보내기 요청에서 현재 권한을 다시 검사한다. |

### 1.2 자료 등록·처리·원문 관리

|---|---|---|---|
| FR-006 | 자료 입력 | 텍스트 붙여넣기와 TXT·MD·텍스트 PDF·DOCX·SRT·VTT 파일 등록을 제공해야 한다. | 형식별 표본에서 본문을 추출하고 원문 위치를 연결한다. 지원하지 않는 형식은 사유를 안내한다. |
| FR-007 | 자료 분류 | 전사문·업무 문서·규정·메모·명단을 구분하고 제목·출처·작성자·자료 언어를 등록·수정할 수 있어야 한다. | 자료 유형과 언어를 사용자가 정정할 수 있으며 혼합언어를 단일 언어로 강제하지 않는다. |
| FR-008 | 날짜·판본 관리 | 회의 일시·시간대, 문서 기준일, 업로드 시각, 규정 판본·시행일·적용 대상을 분리해야 한다. | 값이 없으면 미확인으로 저장하며 업로드 시각을 회의 발생 시점으로 대체하지 않는다. |
| FR-009 | 파일 검사 | 등록 시 파일 형식·실제 내용·크기·추출 가능 여부를 검사해야 한다. | 손상·암호화·이미지 전용 문서는 정상 분석 완료로 표시하지 않고 대체 입력 방법을 안내한다. |
| FR-010 | 처리 상태 관리 | 등록·대기·분석 중·검토 필요·완료·실패·취소 상태와 실패 사유를 표시해야 한다. | 새로고침 후에도 상태가 유지되고, 실패한 작업을 재시도하거나 대기 작업을 취소할 수 있다. |
| FR-011 | 원문 위치 보존 | 문서 식별자·버전과 페이지·문단·발언·시간 구간 중 사용 가능한 위치 정보를 보존해야 한다. | 인용을 선택하면 해당 버전의 정확한 구간이 표시된다. 없는 페이지·시간 정보는 생성하지 않는다. |
| FR-012 | 전사·화자 정정 | 전사 내용과 화자 연결을 수정할 수 있어야 하며 화자 번호·실제 인물·발언에서 언급된 인물을 구분해야 한다. | 수정 전후와 수정자를 조회할 수 있고, 화자 미확인 상태를 유지할 수 있다. |
| FR-013 | 선택적 원음 연결 | 원본 녹음을 전사문과 연결하고 대응 시각이 있는 발언 구간을 재생할 수 있어야 한다. | 원음·대응 시각이 없으면 해당 상태를 표시하고 텍스트 기반 검수는 계속 제공한다. |
| FR-014 | 자료 버전·중복 관리 | 동일 자료의 새 버전을 등록하고 기존 버전과 비교할 수 있어야 한다. 동일 내용의 재등록은 중복 후보로 안내해야 한다. | 새 버전이 기존 원문을 덮어쓰지 않고 중복 등록만으로 결정·업무가 중복 확정되지 않는다. |

### 1.3 다국어·코드스위칭 처리

| ID | 요구사항 | 상세 명세 | 수용 기준 |
|---|---|---|---|
| FR-015 | 세 언어 지원 | 한국어·영어·아랍어로 자료 입력·질문·답변·초안 작성이 가능해야 한다. | 사용자가 결과 언어를 선택할 수 있고 선택 언어로 결과와 확인 상태를 확인한다. |
| FR-016 | 혼합언어 해석 | 한영·영아·한아 및 세 언어 혼합 발언을 전후 맥락과 함께 처리해야 한다. | 언어 전환 지점에서 업무 대상·부정·조건·기한을 분리하거나 누락하지 않는다. |
| FR-017 | 원문·번역 병기 | 결과의 번역문과 원문을 함께 확인할 수 있어야 한다. | 번역문에서 원문 근거로 이동할 수 있고 원문은 번역 결과로 대체되지 않는다. |
| FR-018 | 날짜·수치 해석 | 원문 날짜 표현과 확인된 절대 날짜·시간대를 구분하고 숫자·금액·단위를 보존해야 한다. | 상대 날짜를 결정할 정보가 부족하거나 상충하면 확인 필요로 표시한다. |
| FR-019 | 불명확한 표현 처리 | 생략·지시어·방언·중의적 표현으로 의미가 불명확하면 해당 구간과 확인 질문을 제공해야 한다. | 해석 후보를 확정 사실처럼 제시하지 않으며 나머지 확인 가능한 결과는 제공한다. |

### 1.4 고유명사 탐지·검수·확정

| ID | 요구사항 | 상세 명세 | 수용 기준 |
|---|---|---|---|
| FR-020 | 고유명사 탐지 | 사람·회사·기관 이름과 오류 가능성이 있는 구간을 탐지해야 한다. | 원문 위치·원표기·대상 유형 후보가 표시되고 사용자가 누락된 이름을 직접 지정할 수 있다. |
| FR-021 | 이름 후보 검색 | 참석자 명단·관련 문서·프로젝트 이름 사전에서 후보를 찾아야 한다. | 후보마다 표기·유형·역할 또는 소속·근거를 보여주며 후보 없음 상태를 지원한다. |
| FR-022 | 후보 비교 | 원문, 앞뒤 발언, 후보 표기, 실제 대상, 근거를 나란히 비교할 수 있어야 한다. | 유사 인명·동명이인·같은 약칭의 회사가 각각 독립 후보로 표시된다. |
| FR-023 | 음성 대조 상태 | 음성 대조 완료·미대조·원음 없음 상태를 별도로 관리해야 한다. | 문서나 명단만 확인한 결과를 음성 대조 완료로 표시하지 않는다. |
| FR-024 | 언어별 표기 확인 | 한국어·영어·아랍어 표기를 각각 제안·미확인·확인 완료 상태로 관리해야 한다. | 한 언어의 표기를 확인해도 나머지 언어는 자동 확정되지 않는다. |
| FR-025 | 지칭 대상 연결 | 발언 속 이름이 어느 사람·회사·기관을 가리키는지 별도로 확인해야 한다. | 표기 일치만으로 연결이 확정되지 않고 근거·사용자 확인 기록이 있어야 연결 확인 상태가 된다. |
| FR-026 | 검수 선택지 | 후보 선택·직접 정정·새 대상 등록·고유명사 아님·판단 보류를 제공해야 한다. | 모든 선택을 저장할 수 있고, 후보 선택을 강제하지 않는다. |
| FR-027 | 확정 권한·근거 | 검토 권한을 가진 사용자가 근거 또는 명시적 확인 진술을 남겨 표기·대상 연결을 확정할 수 있어야 한다. | 확정자·시각·근거·대상·언어·자료 버전이 없는 확정 요청은 저장되지 않는다. |
| FR-028 | 적용 범위 선택 | 이번 발언 또는 사용자가 선택한 여러 발언에 정정을 적용할 수 있어야 한다. | 변경 전 대상 목록을 보여주고 선택하지 않은 동일 문자열은 변경하지 않는다. |
| FR-029 | 이름 확인 카드 | 이름·대상·언어별 표기·세 종류의 확인 상태·근거·확인자·시각·적용 구간을 제공해야 한다. | 검색 결과·담당자·초안의 이름에서 같은 확인 카드로 접근한다. |
| FR-030 | 프로젝트 이름 사전 | 대상별 공통 식별자와 언어별 이름·별칭·적용 범위·확인 근거를 관리해야 한다. | 확인된 별칭으로 같은 대상을 찾되 다른 프로젝트로 확인 효력이 자동 확장되지 않는다. |
| FR-031 | 음역·검색 표기 분리 | 자동 생성한 음역·번역·검색용 정규화 표기는 원문 및 확인된 표기와 구분해야 한다. | 자동 음역·모음 보완·문자 정규화만으로 공식 표기나 대상 연결을 확정하지 않는다. |
| FR-032 | 자동 병합 제한 | 이름의 문자열·발음 유사성만으로 사람·회사·기관을 자동 병합하지 않아야 한다. | 유사한 이름이 있는 사례에서 별도 대상을 유지하거나 사용자 확인을 요구한다. |
| FR-033 | 계정·업무 연결 분리 | 이름 확인과 계정 연결·메일 수신자 지정·화자 연결·업무 수락을 분리해야 한다. | 이름 확정만으로 계정·주소·담당 수락·결정 승인 상태가 변경되지 않는다. |
| FR-034 | 연결 취소·재검토 | 잘못 확정한 이름 표기와 대상 연결을 정정·취소할 수 있어야 한다. | 이전 확인 이력이 남고 연결된 업무·위키·답변·초안이 재검토 대상으로 표시된다. |
| FR-035 | 미확인 이름 활용 | 미확인 이름은 원표기와 확인 상태를 표시하고 관련 검토로 연결해야 한다. | 미확인 인물이 확정 담당자로 표시되거나 미확인 회사명이 확정 표기로 초안에 삽입되지 않는다. |

### 1.5 검색·근거 기반 질의응답

| ID | 요구사항 | 상세 명세 | 수용 기준 |
|---|---|---|---|
| FR-036 | 교차 언어 검색 | 질문 언어와 관계없이 세 언어 및 혼합언어 자료를 검색해야 한다. | 한국어·영어·아랍어의 질문·자료 조합 9종에서 정답 근거를 찾을 수 있다. |
| FR-037 | 문맥·별칭 검색 | 정확한 문구를 기억하지 못해도 의미·안건·확인된 이름·별칭으로 정보를 찾을 수 있어야 한다. | 같은 대상의 다국어 기록을 연결하며 유사 이름의 다른 대상은 구분한다. |
| FR-038 | 검색 범위 선택 | 프로젝트·자료 유형·회의 또는 문서 날짜·인물·안건으로 검색 범위를 좁힐 수 있어야 한다. | 적용 범위를 결과에 표시하며 범위 밖 자료는 답변 근거로 사용하지 않는다. |
| FR-039 | 주장별 근거 | 결정·담당자·날짜·금액·규정·이름 관련 사실에 해당 원문 근거를 연결해야 한다. | 주요 사실마다 원문 구간과 버전을 확인할 수 있고 존재하지 않는 인용은 제공하지 않는다. |
| FR-040 | 현재 상태 확인 | 과거 발언을 찾은 뒤 이후 변경·철회·확인 기록을 함께 확인해야 한다. | 과거 제안과 현재 유효한 결정을 구분하고 현재성을 판단할 수 없으면 표시한다. |
| FR-041 | 근거 부족 답변 | 충분한 근거가 없거나 자료가 상충하면 확인 불가·추가 확인 필요를 표시해야 한다. | 누락된 사실을 생성하지 않고, 부족한 정보와 확인 질문을 제공한다. |
| FR-042 | 사실·제안 구분 | 기록된 사실, 사용자 확인, AI의 해석·추천을 구분해 표시해야 한다. | 추천 업무나 추정 이유가 회의 합의·기록된 이유로 제시되지 않는다. |

### 1.6 맥락 브리핑·결정 이력
