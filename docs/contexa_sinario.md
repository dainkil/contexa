# Contexa 최종 서비스 시나리오

> **다국어 회의의 맥락과 근거를 연결하고, 사람·회사·기관의 이름까지 확인해 다음 업무로 이어주는 AI 협업 서비스.**
>
> 작성일: 2026-11-08 · MVP 언어: **한국어·영어·아랍어**
>
> 기존 10개 시나리오에 고유명사 확인·확정 시나리오를 통합한 기획 기준 문서다. 아래 인물·기관·발언·규정·확인 결과는 시연용 가상 설정이며, 실제 구현 완료나 성능 달성을 의미하지 않는다.

## 1. 서비스 정의와 핵심 가치

Contexa는 서로 다른 언어를 사용하는 팀이 **회의 전사문, 업무 문서, 규정집, 메모를 프로젝트 공간에 모아두면, 이전 맥락과 현재 결정을 파악하고 근거를 확인하며 후속 업무까지 수행하도록 돕는 서비스**다.

한국어·영어·아랍어가 섞이는 회의에서는 문장의 뜻뿐 아니라 **누구를 말하는지, 어느 회사인지, 어떤 기관인지**를 확인해야 한다. 이름이 잘못 기록되면 담당자 정리, 과거 정보 검색, 메일 초안까지 같은 오류가 이어질 수 있다. Contexa는 고유명사 검수를 자료 등록부터 결과 활용까지 연결한다.

**핵심 사용자 가치**

1. **맥락을 연결한다.** 여러 회의와 문서에서 현재 상황, 결정의 변화, 남은 조건을 파악한다.
2. **근거를 확인한다.** 답변의 주요 사실을 원문 발언·문단·조항까지 따라가 확인한다.
3. **이름과 대상을 확정한다.** 고유명사의 올바른 표기와 실제 지칭 대상을 근거·사용자 검토로 확인한다.
4. **확인된 내용을 업무로 이어준다.** 할 일, 누적 위키, 보고서·메일·메시지 초안에 같은 정보를 반영한다.

발표용 핵심 문구:

> **“무슨 이야기를 했는지부터, 누구와 어느 회사에 관한 이야기였는지까지. Contexa는 맥락·근거·이름을 확인해 다음 업무로 연결합니다.”**

이 문서에서 **‘고유명사 정확도 확정’은 개별 이름의 표기와 지칭 대상을 근거에 따라 확인하고, 그 확인 상태를 기록한다는 뜻**이다. AI가 모든 이름을 자동으로 맞히거나 서비스 전체의 정확도를 100% 보장한다는 뜻은 아니다. 확인할 수 없는 이름은 미확인으로 남긴다.

## 2. MVP 구성

### 2.1 사용 환경과 지원 범위

| 구분 | MVP 범위 |
|---|---|
| 핵심 사용자 | 여러 회의와 문서를 바탕으로 협업하는 다국어 팀의 구성원·프로젝트 담당자·신규 합류자 |
| 대표 적용 환경 | 한국외대 국제교류 행사 준비팀. 글로벌 프로젝트 팀에도 같은 흐름을 적용 가능 |
| 언어 | 한국어·영어·아랍어 텍스트 입력, 질문, 답변, 초안 작성 |
| 언어 혼용 | 한영·영아·한아 및 세 언어가 섞인 전사문의 맥락·이름·조건 처리 |
| 입력 자료 | 회의 전사문, 행사 기획서, 업무 문서, 운영 지침·규정집, 메모, 참석자·협력사 명단 |
| 입력 방식 | 붙여넣기, TXT·MD·텍스트 PDF·DOCX·SRT·VTT 등록을 목표 범위로 설정 |
| 음성 활용 | 기존 전사문 중심. 원본 녹음과 대응 시각이 있으면 해당 구간 재생, 없으면 문서 근거로 검수 |
| 주요 결과 | 맥락 브리핑, 근거 기반 Q&A, 이름 확인 카드, 결정 이력, 업무 목록, 누적 위키, 다국어 초안 |
| 변경 관리 | 원문·이름·결정 정정 시 관련 결과를 재검토 대상으로 표시하고 갱신안 제공 |
| 실행 범위 | 서비스 내 검토·편집·저장·내보내기. 메일·메시지는 초안 작성까지 |

세 언어를 모두 MVP에 포함한다. 아랍어는 **표준 아랍어 텍스트와 준비된 업무 회의 사례를 우선 평가 범위**로 삼으며, 방언이 섞여 의미가 불명확하면 원문과 확인 필요 상태를 함께 제공한다. 모든 방언의 음성 인식까지 MVP의 완료 조건으로 삼지는 않는다.

한국어·영어·아랍어 질문이 어느 언어의 자료로든 연결되어야 한다. 화면에서는 원문과 선택 언어의 설명을 함께 볼 수 있고, 아랍어의 오른쪽에서 왼쪽으로 쓰는 방향과 혼합 문장의 숫자·영문 이름 표시를 지원한다.

### 2.2 MVP의 구현 깊이

기존 10개 시나리오와 고유명사 검수 1개를 모두 제공하되, 범위를 **사용자가 등록한 프로젝트 자료와 확인된 연결 관계**로 한정한다.

- 충돌 탐지: 같은 안건의 날짜·담당자·금액·조건·이름 연결 중심.
- 변경 영향: 등록 자료, 내부 업무 목록, 위키, 서비스에서 생성한 초안 중심.
- 규정 대조: 업로드한 판본과 적용 정보 중심. 현재 규정인지 불명확하면 표시.
- 이름 검수: 사람·회사·기관을 필수 대상으로 하고, 프로젝트명·행사명은 같은 구조로 확장 가능.
- 녹음 자동 전사, 이름 구간 자동 재인식, 스캔 문서 OCR, 외부 도구 자동 동기화·발송은 후속 확장.

## 3. 대표 시나리오: 회의에 빠진 팀원이 복귀한다

### 3.1 배경

한국어·영어·아랍어를 사용하는 구성원이 국제교류 행사를 준비한다. 회의에서는 발화 중 언어가 바뀌고, 사람 이름과 협력사 이름도 서로 다른 문자와 약칭으로 등장한다.

회의에 빠졌던 민지가 복귀한다. 민지는 **현재 행사 방식, 변경 이유, 인쇄 진행 여부, 아랍어 문구 담당자, 협력사 이름**을 확인하고 업무를 이어가야 한다.

**등록된 시연 자료**

| 자료 | 주요 내용 | 근거 위치 예시 |
|---|---|---|
| 1차 회의 전사문 | 온라인 행사 제안, 일정 논의 | M1 발언 08 |
| 2차 회의 전사문 | 교류 활동을 위해 대면 전환 검토, 장소 확보 필요 | M2 발언 14 |
| 3차 회의 전사문 | 장소 확보 후 대면 개최 확정 발언, 디자인 일정·인쇄 조건·담당자 논의 | M3 발언 09·22·23 |
| 참석자 명단 | 소속·역할과 본인이 확인한 이름 표기 | R1 항목 P-01·P-02 |
| 협력사 소개 문서 | 협력사가 제공한 회사 표기와 프로젝트 내 약칭 | C1 문단 2 |
| 행사 운영 지침 | 외부인 참석 시 사전 승인 조건 | G1 제4조 |
| 개인 메모 | 포스터 목요일 제출이라는 메모 | N1 문단 3 |

시연에서 3차 회의의 대면 개최 결정은 지정 검토자가 확인한 상태로 설정한다. 포스터 제출일은 메모와 전사문이 달라 미확인 상태다. 지침·규정은 시연용 문서이며 실제 학교 규정으로 제시하지 않는다.

### 3.2 이름 오류가 포함된 입력

3차 회의 전사문에는 다음과 같이 적혀 있다.

> “아흐마드가 Arabic copy 맡고, 디자인은 Friday까지 가능해요. But printing is on hold until budget approval. 누르 쪽에는 일정만 확인해 주세요.”

이어지는 발언에는 아랍어로 같은 인쇄 조건이 언급된다.

> “الطباعة معلّقة حتى الموافقة على الميزانية.”
>
> 의미: “예산 승인 전까지 인쇄는 보류입니다.”

여기서 단순 요약만으로는 다음이 해결되지 않는다.

- ‘아흐마드’가 명단 속 어느 사람인지.
- 그 사람의 정확한 아랍어·영어 표기가 무엇인지.
- ‘누르’가 사람인지 협력사인지, 사용할 회사 표기는 무엇인지.
- Friday가 실제 어느 날짜인지, 목요일 메모와 어떻게 다른지.
- 인쇄 보류 조건이 이후 승인으로 해소되었는지.

### 3.3 하나로 이어지는 사용 흐름

| 단계 | 사용자 행동 | Contexa의 처리 | 사용자가 얻는 결과 |
|---|---|---|---|
| 1. 자료 등록 | 전사문·명단·문서·지침·메모 업로드 | 자료 유형·날짜·버전·열람 범위를 구분하고 원문 위치 보존 | 프로젝트 자료함 |
| 2. 이름 검수 | ‘아흐마드’와 ‘누르’의 후보 비교 | 명단·문서·문맥을 대조하고 표기와 대상 연결을 별도로 확인 | 확인된 이름 카드 또는 미확인 상태 |
| 3. 현재 상황 파악 | “지금 어디까지 결정됐어?” | 온라인 제안 → 대면 검토 → 대면 확정의 흐름과 남은 조건 연결 | 근거가 붙은 복귀 브리핑 |
| 4. 업무 조건 확인 | “인쇄도 진행해도 돼?” | 혼합언어 발언과 이후 승인 기록 검색 | 예산 승인 확인 전 인쇄 보류, 일정 문의는 별도 업무 |
| 5. 규정·충돌 확인 | “외부인 초대와 제출일은 문제없어?” | 지침 대조, 목요일 메모와 Friday 발언 비교 | 사전 승인 필요, 제출일 확인 질문 |
| 6. 내 할 일 확인 | “내 일과 아랍어 문구 담당자 정리해줘.” | 확인된 인물 연결·업무 수락 기록을 반영하고 미정 항목 표시 | 담당자별 업무·조건·기한 |
| 7. 초안 작성 | “진행 보고서와 협력사 영어 메일, 팀 공지 아랍어 초안 써줘.” | 같은 확인된 사실을 목적·언어별로 구성 | 이름·상태·조건이 일관된 세 종류의 초안 |
| 8. 변경 반영 | 이름이나 일정 오류 정정 | 영향을 받는 업무·위키·답변·초안을 표시 | 변경 전후 비교와 재검토·갱신 |

**대표 경험의 완성:** 복귀한 팀원이 ‘현재 무엇이 결정됐고, 누가 맡았으며, 어느 회사에 무엇을 요청해야 하는가’를 이름과 근거까지 확인한 상태로 업무를 이어간다.

## 4. 핵심 차별 시나리오 — CX-11. 고유명사의 표기와 지칭 대상을 확인·확정한다

기존 시나리오 번호 CX-01~10은 유지하고, 새 핵심 시나리오 CX-11을 대표 흐름의 앞부분에 배치한다.

### 4.1 상황과 요청

전사문에는 ‘아흐마드’, ‘Ahmed’, ‘누르’가 등장한다. 참석자 명단에는 이름이 비슷한 사람이 둘 있고, 회사 이름은 한글 약칭으로만 기록되어 있다.

사용자 요청:

> **“아랍어 문구 담당자가 정확히 누구야? 사람 이름과 회사 이름을 명단·문서랑 대조해서 사용할 표기까지 확정해줘.”**

### 4.2 후보를 비교한다

아래 표기는 가상 인물이 프로젝트에서 제공·확인한 표기라는 설정이다. 아랍어에서 기계적으로 생성한 영문 음역을 공식 표기로 취급하지 않는다.

| 대상 | 아랍어 표기 | 영어 표기 | 프로젝트 내 표기 | 후보 판단에 쓸 정보 |
|---|---|---|---|---|
| P-01 | أحمد حسن | Ahmed Hassan | 아흐마드 하산 | 아랍어 문구 검토 역할, 관련 업무 확인 기록 |
| P-02 | أحمد حسين | Ahmed Hussein | 아흐마드 후세인 | 현장 운영 역할, 별도 인물 |
| O-01 | نور | NUR Labs | 누르 | 협력사 소개 문서에 등록된 이름·약칭 |

‘아흐마드’라는 문자열만으로 P-01을 확정하지 않는다. Contexa는 두 사람을 후보로 보여주고 **해당 발언의 전후 문맥, 참석자 역할, 업무 확인 기록**을 함께 제시한다. ‘누르’도 해당 프로젝트의 회사 문서와 문맥이 연결되는지 검토한다.

### 4.3 세 종류의 확인을 분리한다

| 확인 종류 | 확인할 질문 | 확인 근거 | 화면 상태 예시 |
|---|---|---|---|
| 음성 대조 | 실제 발음이 전사와 맞는가? | 대응 원음 구간과 청취 검토 | 대조 완료 / 미대조 / 원음 없음 |
| 표기 확인 | 이 대상의 사용할 이름 표기가 맞는가? | 본인 확인 명단, 회사 제공 문서, 사용자 정정 | 아랍어 확인 / 영어 확인 / 한국어 미확인 |
| 대상 연결 | 이번 발언이 실제 어느 사람·회사·기관을 가리키는가? | 전후 발언, 역할·소속, 해당 업무에 대한 확인 | 연결 후보 / 연결 확인 / 보류 / 연결 취소 |

**명단에 이름이 있다는 사실, 그 발언이 해당 사람을 가리킨다는 사실, 그 사람이 업무를 수락했다는 사실은 각각 확인한다.** 이름이 확인되어도 업무 배정이나 결정 승인 상태가 저절로 바뀌지 않는다.

### 4.4 사용자가 검토하고 확정한다

1. 오류 가능성이 있는 이름과 이름 후보를 표시한다.
2. 원문, 앞뒤 발언, 후보별 이름·역할·근거를 나란히 보여준다.
3. 원음과 대응 구간이 있으면 재생해 확인할 수 있게 한다.
4. 사용자는 **후보 선택 / 직접 정정 / 새 대상 등록 / 고유명사 아님 / 판단 보류** 중 하나를 선택한다.
5. 이번 발언에만 적용할지, 검토한 여러 발언에 적용할지 선택한다.
6. 권한 있는 검토자의 확인과 해당 자료 버전을 기록해 저장한다.
7. 관련 검색·업무·위키·초안의 갱신 대상을 보여준다.

확정 카드에는 **이름, 대상, 확인된 언어별 표기, 근거, 확인자, 확인 시각, 적용 발언, 자료 버전**을 표시한다. 원본 전사문은 보존하고 교정된 표기를 별도로 보여준다.

### 4.5 대표 결과

시연에서는 P-01 본인이 해당 발언이 자신을 가리킨다고 확인하고 아랍어 문구 검토 업무를 수락한다. 프로젝트 검토자는 회사 문서와 발언 문맥을 대조해 ‘누르’를 O-01로 연결한다.

| 항목 | 확인 전 | 확인 후 |
|---|---|---|
| 담당 인물 | ‘아흐마드’, P-01/P-02 중 미확인 | P-01: أحمد حسن / Ahmed Hassan |
| 업무 수락 | 발언에서 추출한 담당 후보 | P-01 본인의 해당 업무 수락 확인 |
| 협력사 | ‘누르’, 대상 유형 미확인 | O-01: نور / NUR Labs |
| 음성 확인 | 원음 없음 | 원음 없음 유지; 명단·문맥·사용자 확인으로 검수 |
| 후속 활용 | 담당자·회사명이 미확인인 초안 | 확인된 표기로 새 초안 생성, 기존 초안은 재검토 표시 |

**사용자가 체감하는 결과:** 한국어 질문에서 찾은 담당자를 아랍어 원문 표기로 확인하고, 영어 보고서와 메일에도 동일한 인물·회사를 일관되게 사용할 수 있다.

### 4.6 반드시 처리할 예외

- 비슷한 이름이나 같은 영문 표기만으로 서로 다른 사람·기관을 합치지 않는다.
- 이름 후보가 없으면 새 대상을 등록하거나 보류할 수 있다.
- 확인되지 않은 음역·번역은 ‘제안 표기’로 표시한다. 확인되지 않은 언어의 표기를 억지로 채우지 않는다.
- 하나의 발언을 정정해도 모든 동일 문자열을 일괄 치환하지 않는다.
- 이름 확인만으로 로그인 계정, 메일 주소, 업무 담당자를 자동 지정하지 않는다.
- 화자 번호와 실제 인물을 별도로 연결한다. 언급된 사람과 발언자를 혼동하지 않는다.
- 잘못 연결한 대상은 연결을 취소하고, 해당 연결을 사용한 결과도 재검토한다.

## 5. 전체 사용자 시나리오

### CX-01. 이전 회의 맥락과 현재 상황을 파악한다

**상황:** 신규 합류자나 회의 불참자가 전사문·기획서·메모 여러 개를 읽어야 한다.

**요청:** “지금까지 어떤 이야기가 진행됐고, 현재 어디까지 결정됐는지 알려줘.”

**동작:** 회의를 가로질러 목표, 논의 흐름, 현재 확인된 결정, 변경 이유, 미해결 조건을 연결한다. 누적 위키를 활용하되 주요 사실은 원문과 검토 기록으로 확인한다.

**결과:** “온라인 개최가 제안됐으나 교류 활동을 위해 대면 전환을 검토했고, 장소 확보 후 대면 개최가 확인되었습니다. 인쇄 예산 승인과 외부인 참석 승인은 별도 확인이 필요합니다.” 각 사실에 근거를 붙인다.

**완료 기준:** 회의별 요약을 넘어 현재 상태와 변화가 드러나며, 변경 이유가 없으면 ‘기록 없음’으로 표시한다.

### CX-02. 언어와 표현이 달라도 이전 정보를 찾는다

**상황:** 한국어로 기억하는 내용이 영어·아랍어 또는 혼합언어 자료에 있다.

**요청:** “참가비를 무료로 하자는 얘기는 누가 했어? 확정된 거였어?”

**동작:** 세 언어의 관련 발언과 후속 논의를 검색한다. 확인된 이름·별칭을 활용해 같은 대상의 기록을 찾되, 이름이 비슷한 다른 대상의 기록은 구분한다.

**결과:** 발언자 또는 미확인 화자, 회의 날짜, 원문 구간, 제안·확정 여부, 이후 변경을 제공한다.

**완료 기준:** 질문 언어와 자료 언어가 달라도 근거에 도달한다. 발언자 연결이 확인되지 않았다면 실명으로 단정하지 않는다.

### CX-03. 코드스위칭 발언의 조건과 업무 범위를 이해한다

**상황:** 한 발화에서 한국어·영어가 섞이고, 이어지는 아랍어 발언에 중요한 조건이 있다.

**요청:** “금요일까지 무엇을 끝내는 거야? 인쇄도 진행해도 돼?”

**동작:** 혼합언어의 앞뒤 맥락을 연결하고 디자인 완료 가능 시점과 인쇄 승인 조건을 분리한다. 부정·조건·담당자·기한·수치를 보존한다.

**결과:** “디자인은 Friday까지 가능하다는 발언이 있습니다. 인쇄는 예산 승인 전까지 보류입니다. 제출일은 메모와 충돌하므로 확인이 필요합니다.” 원문과 선택 언어 설명을 함께 보여준다.

**완료 기준:** ‘가능하다’를 ‘완료됐다’로 바꾸지 않으며, 예산 승인 조건을 생략하지 않는다. 상대 날짜를 확정할 정보가 없으면 확인을 요청한다.

### CX-04. 답변의 근거를 확인하고 규정과 대조한다

**상황:** 회의에서는 외부인 참석에 문제가 없다고 말했지만 등록 지침에는 사전 승인 조건이 있다.

**요청:** “외부인 초대해도 되는 거 맞아? 근거도 보여줘.”

**동작:** 회의 주장과 규정 내용을 분리하고 판본·적용 대상·시행 정보·조건을 대조한다.

**결과:** 회의 발언과 지침 조항을 나란히 제시하고, 승인 기록 유무와 추가 확인 사항을 보여준다.

**완료 기준:** 파일명뿐 아니라 실제 발언·페이지·조항·문단으로 이동할 수 있다. 지침의 현행 여부를 확인하지 못하면 그 상태를 표시한다.

### CX-05. 담당자별 해야 할 일을 정리한다

**상황:** 담당자·기한·선행 조건이 여러 발언에 흩어져 있고 이름 오류도 있다.

**요청:** “이번 회의에서 나온 할 일을 사람별로 정리해줘. 나는 뭘 먼저 해야 해?”

**동작:** 업무·담당 후보·기한·산출물·조건을 추출하고, 이름 연결 및 업무 수락 상태를 확인한다.

| 업무 | 담당자 | 기한 | 조건·상태 |
|---|---|---|---|
| 포스터 디자인 | 민지 | 목요일/Friday 충돌, 확인 필요 | 담당 수락 확인 |
| 아랍어 문구 검토 | أحمد حسن / Ahmed Hassan | 미정 | 인물 연결 및 업무 수락 확인 |
| 인쇄 발주 | 미정 | 미정 | 예산 승인 확인 전 보류 |
| 영어 문구 추가 검토 | 미정 | 미정 | AI 추천 업무, 회의 합의와 구분 |

**완료 기준:** 미정 담당자·기한을 임의로 채우지 않는다. 확인된 이름, 담당 수락, 업무 완료를 서로 다른 상태로 보여준다.

### CX-06. 보고서·메일·메시지 초안을 작성한다

**상황:** 같은 회의 결과를 교수, 협력사, 팀원에게 서로 다른 언어와 형식으로 전달해야 한다.

**요청:** “교수님께 드릴 한국어 보고서, 협력사 영어 메일, 팀원용 아랍어 공지를 써줘.”

**동작:** 현재 확인된 결정과 업무 상태, 공유 가능한 근거를 바탕으로 목적·언어별 초안을 작성한다. 이름은 확인된 표기를 재사용하고 미확인 이름은 확인 항목으로 남긴다.

**결과:** 보고서는 현황·결정·미해결 사항, 영어 메일은 NUR Labs에 대한 일정 문의, 아랍어 공지는 담당 업무와 인쇄 보류 조건을 담는다. 사실별 근거는 검토 화면에서 확인한다.

**완료 기준:** 문의 메일을 발주 확정 메일로 바꾸지 않는다. 미확정 일정·승인을 확정으로 쓰지 않으며, 세 언어에서 이름·조건·기한이 일관되어야 한다. 사용자가 편집·복사·내보내기할 수 있고 자동 발송하지 않는다.

### CX-07. 결정이 왜 바뀌었는지 추적한다

**상황:** 초기 기획서는 온라인 행사인데 최근 회의에서는 대면 행사를 전제로 한다.

**요청:** “왜 대면으로 바뀐 거야? 언제, 누가 확인했어?”

**동작:** 최초 제안, 대안 검토, 조건 충족, 확정 발언, 지정 검토자의 확인 기록을 시간순으로 연결한다.

**결과:** 변경 전후, 기록된 이유, 근거, 확인자, 남은 조건을 타임라인으로 제공한다.

**완료 기준:** 최신 제안이 기존 결정을 자동으로 대체하지 않는다. 행사 방식 변경과 날짜·예산·장소의 변경을 각각 구분한다.

### CX-08. 모순되거나 빠진 정보를 찾아 확인한다

**상황:** 전사문과 메모의 제출일이 다르고, 최종 검토 담당자는 없으며 일부 이름의 대상 연결도 불명확하다.

**요청:** “업무 시작 전에 서로 안 맞거나 빠진 내용을 찾아줘.”

**동작:** 같은 안건의 날짜·담당자·금액·조건을 비교하고, 미확인 이름과 정보 누락을 함께 보여준다.

**결과:** 충돌하는 원문, 누락 항목, “목요일은 내부 검토이고 Friday는 최종 제출인가요?” 같은 확인 질문을 제공한다.

**완료 기준:** 그럴듯한 설명으로 충돌을 임의 해결하지 않는다. 확인자의 답변과 근거가 있어야 해당 상태를 갱신한다.

### CX-09. 이름이나 결정 정정의 영향을 후속 결과에 반영한다

**상황:** 행사 날짜가 바뀌거나 ‘아흐마드’가 다른 사람으로 잘못 연결된 사실을 발견한다.

**요청:** “이 내용 고치면 같이 수정해야 할 업무랑 문서가 뭐야?”

**동작:** 정정된 원문·이름·결정을 참조한 업무, 위키, 기존 답변, 초안을 찾아 재검토 표시와 수정안을 만든다. 원문과 확인 이력은 보존한다.

**결과:** 변경 전후 비교, 영향받은 항목, 새로 확인할 담당자·이름, 갱신 상태를 제공한다.

**완료 기준:** 기존 확정 결과를 조용히 덮어쓰지 않는다. 등록되지 않은 외부 문서와 이미 복사해 사용한 초안은 자동으로 수정할 수 없음을 확인 범위에 표시한다.

### CX-10. 다음 회의에서 결정할 것을 준비한다

**상황:** 지난 회의 이후 새 문서와 확인 기록이 추가됐지만 미해결 안건이 남아 있다.

**요청:** “지난번 이후 달라진 내용과 이번 회의에서 결정해야 할 걸 정리해줘.”

**동작:** 변경된 결정, 업무 진행 입력, 승인 대기, 미확인 이름, 충돌·누락을 묶는다.

**결과:** 회의 전 브리핑, 결정할 질문, 이름 확인 목록, 필요한 자료, 관련 담당자를 제공한다.

**완료 기준:** 기록이 없는데 업무 완료를 추정하지 않는다. 각 언어의 참석자가 같은 안건과 확인 상태를 볼 수 있다.

### CX-11. 고유명사의 정확한 표기와 대상을 확정한다

**상황:** 사람·회사·기관의 이름이 오전사되거나 여러 언어·별칭으로 등장한다.

**요청:** “이 이름이 누구 또는 어느 회사를 말하는지 확인하고, 정확한 표기로 정리해줘.”

**동작:** 이름 탐지 → 후보·근거 비교 → 선택적 원음 대조 → 언어별 표기 확인 → 대상 연결 확인 → 사용자 확정 → 후속 결과 반영.

**결과:** 확인 상태와 근거가 있는 이름 카드, 프로젝트 이름 사전, 일관된 검색·업무·초안.

**완료 기준:** 4장의 검수 흐름이 작동하며, 이름이 확인되지 않아도 판단 보류로 작업을 계속할 수 있다. 보류된 이름은 결과에서 확인된 이름처럼 사용하지 않는다.

## 6. 세 언어에서 동일하게 유지할 정보

| 항목 | 일관성 규칙 |
|---|---|
| 원문 | 입력된 언어·문자·표기와 자료 버전을 보존 |
| 사람·회사·기관 | 같은 대상은 공통 식별자로 연결하고 언어별 확인 표기를 별도로 관리 |
| 이름 별칭 | 프로젝트 범위와 확인 근거를 기록. 유사 표기는 후보 검색에 쓰고 자동 병합 근거로 쓰지 않음 |
| 결정·업무 | 언어를 바꿔도 같은 항목·버전·상태를 표시 |
| 부정·조건 | ‘보류’, ‘승인 후’, ‘미정’이 번역과 초안에서도 유지 |
| 숫자·날짜 | 원문 표현과 확인된 날짜·시간대를 구분하고 값의 변형 여부 확인 |
| 근거 | 번역문에서도 동일한 원문 발언·문단으로 이동 |
| 아랍어 표시 | 오른쪽에서 왼쪽으로 읽는 본문과 영문 이름·숫자 혼합 표시, 선택·복사·편집 결과 확인 |
| 미확인 항목 | 답변 언어를 바꿔도 미확인·보류·재검토 상태 유지 |

예를 들어 한국어로 ‘아흐마드 하산’을 검색하고 아랍어 자료를 찾은 뒤 영어 초안을 작성하더라도, **세 결과는 같은 인물 P-01과 같은 확인 기록을 참조**해야 한다. 한국어 표기가 미확인이라면 확인된 원문 이름과 미확인 안내를 보여준다.

## 7. MVP 화면 구성

| 화면 | 사용자가 하는 일 | 핵심 표시 |
|---|---|---|
| 프로젝트 홈 | 복귀 브리핑과 현재 상태 확인 | 현재 결정, 남은 조건, 내 업무, 이름·결정 검토 요청 |
| 자료함·원문 뷰어 | 자료 등록, 근거 열기, 전사 정정 | 원문/번역, 발언·문단 위치, 날짜·판본·권한, 선택적 원음 |
| 이름 검토함 | 후보 비교, 표기·대상 확인, 연결 취소 | 세 종류의 확인 상태, 언어별 표기, 근거, 적용 범위 |
| 질문·근거 화면 | 과거 정보 검색, 규정·충돌 확인 | 답변, 원문 근거, 미확인 항목, 현재 상태 |
| 결정·업무·위키 | 변경 이력, 담당 업무, 누적 맥락 확인 | 버전, 확인자, 담당 수락, 조건, 정정 영향 |
| 초안 작성 화면 | 보고서·메일·메시지 생성·편집 | 출력 언어, 사용한 이름, 주요 사실 근거, 재검토 표시 |

이름 검토는 별도 검토함뿐 아니라 **답변의 이름, 업무 담당자, 초안의 회사명을 눌러서도 진입**할 수 있어야 한다.

## 8. 공통 동작 원칙

1. **근거와 추론을 구분한다.** 기록에 있는 사실, AI가 제안한 해석·업무, 사용자가 확인한 내용을 구별한다.
2. **확인 대상을 구분한다.** 이름 표기, 대상 연결, 화자 연결, 업무 수락, 결정 승인, 조건 충족은 별도 확인이다.
3. **원문을 보존한다.** 정정은 새 버전으로 저장하고 기존 인용에 정정·재검토 상태를 연결한다.
4. **권한 안에서 검색하고 작성한다.** 개인 메모는 공용 위키나 외부 공유용 초안에 무단 반영하지 않는다.
5. **정정을 후속 결과까지 연결한다.** 이름을 수정했다면 관련 업무·답변·위키·초안의 영향도 확인한다.
6. **모르는 것은 미확인으로 둔다.** 근거 부족, 후보 충돌, 자료 시점 불명확을 사용자에게 보여준다.
7. **입력 부족에도 가능한 부분을 제공한다.** 원음이 없으면 텍스트 검수를 제공하고, 담당자가 미정이면 나머지 업무 정보는 정리한다.

## 10. 완료 기준과 정확도 검증

### 10.1 MVP 수용 시나리오

| 시험 | 기대 결과 |
|---|---|
| 세 언어 사이의 교차 검색 | 한국어·영어·아랍어 질문 각각에서 다른 두 언어의 정답 근거를 찾음 |
| 혼합언어 조건 추출 | 인쇄 보류·예산 승인 조건이 요약·업무·초안에 모두 유지됨 |
| 유사 인명 두 명 | 후보 비교 후 근거가 부족하면 보류하며 자동 병합하지 않음 |
| 사람과 회사가 같은 약칭 사용 | 문맥과 문서로 대상 유형을 구분하고 모르면 미확인 표시 |
| 미등록 이름 | 후보 없음, 새 대상 등록, 판단 보류를 지원 |
| 일부 언어 표기만 확인됨 | 확인된 표기는 사용하고 나머지는 제안·미확인으로 구분 |
| 원음 없음 | 텍스트·명단 검수는 가능하나 음성 대조 완료로 표시하지 않음 |
| 화자·담당자 구분 | 언급된 사람을 발언자나 업무 수락자로 자동 처리하지 않음 |
| 확정 후 잘못된 연결 취소 | 연결 이력 보존, 관련 결과 재검토, 정정 후 새 결과 생성 |
| 이름 정정 적용 범위 | 선택한 발언만 수정되고 같은 문자열의 다른 대상은 유지됨 |
| 결정·규정 충돌 | 출처를 나란히 제시하고 해결 근거 없이 확정하지 않음 |
| 아랍어 표시·복사·편집 | 영문 이름·숫자와 섞여도 표시 및 복사 결과의 의미·표기가 유지됨 |
| 자료 권한·공유 범위 | 볼 수 없는 자료는 답변 근거에 섞이지 않고 개인 메모는 공용 결과에 무단 반영되지 않음 |
| 세 언어 초안 생성 | 현재 결정·확인된 이름·미확인 조건이 언어 간 일관됨 |

### 10.2 고유명사 품질은 별도로 측정한다

| 지표 | 측정할 내용 |
|---|---|
| 이름 탐지 성능 | 정답 고유명사 중 찾은 비율과, 고유명사가 아닌 구간을 잘못 표시한 비율 |
| 후보 포함률 | 정답 대상이 제시된 후보 목록에 포함되는 비율 |
| 표기 정확도 | 확인된 표기가 본인·기관 제공 기준 표기와 맞는 비율. 언어별로 측정 |
| 대상 연결 정확도 | 확정된 연결이 실제 지칭 대상과 맞는 비율 |
| 잘못된 확정 | 근거가 부족하거나 대상이 다른데 확인 완료로 처리한 사례 수 |
| 보류 적절성 | 정답을 정할 수 없는 사례를 보류하는지, 답할 수 있는 사례를 과도하게 보류하는지 |
| 후속 반영 | 정정 영향이 있는 업무·위키·초안을 빠짐없이 재검토 대상으로 표시하는지 |
| 검토 부담 | 이름 하나를 확인하는 데 걸린 시간, 후보 수정·재확인 횟수 |

평가는 **AI 후보 단계와 사용자 검수 후 결과를 나누고**, 한국어·영어·아랍어·혼합언어 결과를 각각 보고한다. 전체 문장 정확도가 높다는 이유로 이름 정확도를 대신 설명하지 않는다. 비교 실험에서는 검수 전후의 잘못된 이름·대상 연결 수와 사용자의 확인 시간을 함께 본다.

평가용 정답은 모델 출력과 독립적으로 준비하고, 아랍어 표기·의미는 해당 언어를 검토할 수 있는 사람이 확인한다. 현재 문서는 측정 방법과 완료 동작을 정한 것이며, 실제 정확도 수치와 통과 결과는 구현 후 평가 기록으로 제시한다.

## 11. 기획서·발표용 최종 소개문

**Contexa는 한국어·영어·아랍어가 섞인 회의 전사문과 업무 문서·규정·메모를 연결해, 이전 맥락과 현재 결정, 그 근거와 다음 할 일을 정리하는 AI 협업 서비스입니다. 특히 전사 과정에서 잘못 기록될 수 있는 사람·회사·기관 이름을 참석자 명단과 관련 문서, 선택적 원음 대조, 사용자 검토로 확인해 정확한 표기와 지칭 대상을 확정합니다. 확인된 이름과 업무 정보는 검색·위키·보고서·메일·메시지 초안에 일관되게 반영되며, 정정이 생기면 관련 결과까지 재검토하도록 연결합니다.**
