# 합성 평가 자료

국제교류 행사 준비팀의 회의 4회와 문서 2건이다. 실제 사람의 회의가 아니라 평가용으로 지어낸 것이다.
시연 데이터(`server/.../dev/DemoSeed.java`)의 회의를 늘려 아래 상황을 모두 넣었다.

| 상황 | 어디에 |
| --- | --- |
| 온라인 행사 → 대면 행사로 변경 | m1:1 제안 → m2:1 대면 제안 → m3:1 확정 |
| 예산 승인 여부에 따른 일정 조정 | m3:6 "예산이 안 나오면 일주일 미루자"(제안) |
| "승인되면 진행하자" 같은 조건부 결정 | m2:3 인쇄 보류, m3:4 "승인이 나면 바로 진행", m4:6 승인 |
| 같은 인물의 다국어 표기 | Ahmed · 아흐마드(m2:6) · أحمد(명단) |
| 잘못 기록된 이름의 정정 | m4:2 "강당 예약 담당이 지윤 씨로 적혀 있었는데 지훈 씨가 맞다"(날짜 정정은 아직 없다) |
| 제안·검토 의견(확정이 아닌 발언) | m1:1, m1:2, m1:5, m2:1, m2:5, m3:6, m3:7, m4:5 |
| 한 발언 안의 언어 섞임 | m1:6, m3:5 |

## 파일

- `corpus.json`: 문서 목록(id, 제목, 종류, 파일)
- `documents/*.txt`: 원문. 앱에서 그대로 올려 볼 수도 있다
- `labels/extract.json`: 회의마다 뽑아야 하는 카드와 줄(뽑기 평가)
- `labels/retrieval.json`: 질문마다 찾아야 하는 발언(검색 평가)

발언은 `문서 id:번호`로 가리킨다. 번호는 일꾼과 같은 규칙(`ai/contexa_ai/parse.py`)으로 자른 순서이고 1부터 센다.
전사문은 줄마다, 명단·문서는 빈 줄로 나뉜 문단마다 하나다. 원문의 줄을 바꾸면 라벨의 번호도 같이 고쳐야 한다
(`eval/tests/test_labels.py`가 어긋남을 잡는다).

## 뽑기 라벨 규칙

- `evidence`는 그 카드가 나온 발언 번호다. 모델이 댄 근거가 하나라도 겹치고 종류가 같으면 같은 카드로 본다.
  인물·기관(`ENTITY`)은 근거 대신 `names`의 표기 중 하나와 같으면 같은 카드다.
- 결정 사건의 `kinds`는 맞는 것으로 볼 사건 종류다. 해석이 갈리면 여럿을 적는다(예: 미루자는 말은 DEFERRAL·DISCUSSION).
- `optional: true`는 뽑아도 되고 안 뽑아도 되는 것이다. 맞혀도 세지 않고 놓쳐도 틀리지 않는다.
  optional 카드에 걸린 줄도 optional이다. 정답이 하나로 정해지지 않는 것만 optional로 둔다.
- 다음 회의를 뽑을 때는 앞 회의의 필수 정답 카드와 `carry: true` 카드를 "이미 있는 카드"로 보여 준다.
  사람이 확인했다고 보는 것이다. 회의 간 줄(이미 있는 카드에 잇는 줄)은 그래서 따로 잴 수 있다.
- `not_decided`는 아무것도 확정하지 않은 발언이다. 근거가 모두 여기에 있는 DECISION·CHANGE 사건은
  "확정되지 않은 발언을 확정으로 뽑음"으로 센다.
- 채점하지 않는 줄: EVIDENCED_BY·MENTIONS(카드의 근거로 따로 잰다), SPOKEN_BY(화자 표기에서 바로 나온다),
  DERIVED_FROM(어느 결정에서 나온 일인지는 해석이 갈린다).
- 담당자가 원문에 없으면 담당 줄을 정답에 넣지 않는다. m3:4 "발주 담당은 그때 정하고요"에 담당을 걸면 틀림이다.

## 검색 라벨 규칙

- `relevant`는 질문에 답하려면 봐야 하는 발언이다. 같은 내용이 다른 언어로만 적혀 있어도 넣는다.
  다른 언어 발언을 찾는지가 다국어 검색에서 재려는 것이기 때문이다.
- `langs`는 질문의 언어다. 섞어 쓴 질문은 둘 다 적는다.
